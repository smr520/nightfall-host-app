# 存档边界修复与验证

本轮范围是读档保护、可靠归档、已知 v1 旧档迁移和行动草稿生命周期；不重写主持规则，不将本地自动化通过视为真机验收。

## 实现边界

- 启动分别读取会话与历史（`Promise.allSettled`）。失败不等于空存档；读取错误持续显示，禁止新建、修改和覆盖。
- 储存服务在成功读取两类记录前拒绝写入。损坏历史逐条隔离；修复、移除或替换前备份完整原始字符串，备份失败则停止破坏性操作。
- 页面可重试读取/保存、经隐私确认分享原始数据、确认备份后清除异常会话。恢复备份包含全部身份，不应公开分享。
- 可合并的 CURRENT 快照与必须执行的归档/删除命令分开排队。清空或新局不能取消历史命令；结束后立刻撤销仍按序移除归档。
- 新局替换已结束旧局时先补齐旧局归档，避免先前历史写入失败导致永久丢失。
- 校验 schema、阶段、角色、座位唯一性、桌规、夜间行动、投票、技能队列、事件与公告类型。未知 schema 不猜测转换。
- 已知 v1 提前死亡状态在公布前兼容迁移；旧档公告缺失由夜间行动推导，死亡/警徽状态冲突则保留原档并要求恢复。
- 选座、药品、裁定原因、投票草稿在阶段/轮次/天数或撤销重做时失效；身份显示偏好保留。切换阶段滚动至顶部。
- 保存故障独立于普通操作错误，回首页仍显示；保存期间禁止替换或移除。

## 测试入口

```text
npm run typecheck
npm run lint
npm run test:engine
npm run test:regressions
npm run test:ui
npx expo-doctor
npx expo export --platform android
```

`test:ui` 运行所有 Jest 测试，包括组件、队列和使用可注入 KV 存储的真实储存服务测试，不只测试 mock 掉的 storage 函数。

## 不在本轮验收范围

- Android 真机 SQLite、系统分享面板、键盘、安全区和强杀重启需要设备测试。
- CURRENT 与 HISTORY 是顺序 KV 写入，并非跨键事务；异常退出后在恢复/替换/移除边界补齐归档。
- 50 个完整撤销快照仍待性能基准，尚未改成增量日志。
- 恢复备份不自动删除，以数据安全优先；长期备份空间管理待后续设计。
- 真实 Release APK CI 构建成功后，才能确认当前 Runner 的 SDK/Gradle 兼容性。
