# 主持工具重构与验证记录

日期：2026-11-14。此次工作保留了之前的个性化方案和角色图鉴，只修改本地源码与测试，没有生成、上传或发布安装包。

## 结构调整

实际应用入口为 `index.ts → App.tsx`。开源发布树不包含旧网页原型 `index.html` 和未接入的早期规则目录，避免让维护者误把它们当成运行代码；当前执行规则只在 `src/game`。

| 模块 | 责任 |
| --- | --- |
| `src/game/flow.ts` | 自定义夜间顺序、角色变化后的顺序同步、流程配置校验及天亮出局原因集合 |
| `src/game/narration.ts` | 按座位生成口播、替换自定义模板变量、区分私密行动提示与公开台词 |
| `src/game/preferences.ts` | 与界面无关的主持方案模型、校验和旧数据兼容 |
| `src/hooks/useHostingPreferences.ts` | 偏好读取、失败恢复、写入锁、默认方案选择和编辑 |
| `src/hooks/useSpeechClock.ts` | 按实际时间计算倒计时，保留跨页签的发言人、方向和计时状态 |
| `src/ui/setup/WorkflowSettings.tsx` | 夜间顺序、天亮复核、发言时长和自定义主持词编辑 |
| `src/ui/game/DawnReview.tsx` | 私密天亮预览、人工出局名单与死亡原因复核 |
| `src/ui/game/SpeechTimer.tsx` | 发言人选择、顺号或逆号、下一位、暂停与重置操作 |

`src/ui/preferences.ts` 保留兼容导出，存储模块直接依赖游戏领域模型，避免存储层依赖界面目录。旧存档、旧偏好、现有撤销重做和历史恢复路径继续保留。

## 界面方向

采用现有 `ui-ux-pro-max` 和 React Native 规范中的手机交互建议，最终设计以用户的白色界面偏好为准。白色内容区、浅灰背景、墨色操作；状态色仅用于警告、阵营或当前选择。

首页优先展示进行中对局，开局方式用整行选择，设置、资料、复盘归入工具列表。主持台突出口播和座位，记录改为时间线，图鉴改为平面目录。全局按钮允许文字换行；座位网格依据实际宽度和字体缩放调整列数。此次没有更换运行依赖。

## 已增加的可用功能

- 自定义方案可持久保存夜间行动顺序、主持词、发言时长、手动天亮复核开关。
- 夜间行动可重排；当前阵容的必要行动必须完整，女巫必须在狼人刀口之后行动。
- 自定义主持词支持 `{目标}`、`{候选人}`、`{投票人}`、`{发言人}`、`{昨夜结果}`；清空后恢复默认台词。
- 公开环节使用明确座位号，例如发言人、候选人、投票人和警徽接任者；夜间行动角色座位列在私密提示中。
- 发言计时支持 15–1800 秒，提供常用时长、暂停、恢复、重置、顺逆号及下一位。跨页签保留，返回首页或重启后不恢复正在运行的计时。
- 天亮人工复核可调整出局座位和原因，填写原因后才能确认；实际死亡技能、警徽和胜负仍由正常流程执行。
- 开局座位页支持随机分配当前阵容中的身份，保留座位和姓名。

## 修复的问题

- 存档中的 `nightCalls` 与角色构成不一致时，不再静默跳过角色行动。
- 方案中的非法夜间顺序、重复行动、未知主持词阶段、非文本主持词会被校验隔离。
- 通用角色记录动作不能绕开狼人、守卫、预言家和女巫的专用技能校验。
- 手动天亮名单拒绝不存在、重复或已经出局的座位，拒绝非法死亡原因及不足两字的复核原因。
- 从人工名单移除再加回原本中毒的猎人时，保留原始中毒原因，并提供显式原因选择，避免错误获得开枪机会。
- 未公布的昨夜死亡不标为可公开播报的日志；竞选中的自定义结果变量也不会提前披露名单。
- 发言计时与方向不因切换座位、记录等页签丢失。
- 自定义主持词留空或仅空格时正确回退到标准口播。

## 仍需按玩法单独实现的部分

角色图鉴有介绍，不代表全部特殊牌技能已经自动结算。骑士决斗、守墓人信息反馈、摄梦与噩梦封锁、商人技能授予、特殊刀权及第三方胜负仍需逐项建模和验证。手动天亮复核仅确认本夜出局结果，不会自动完成这些技能的次数、能力转移或阵营变化。

后续较实用的功能方向是：独立记录警上退水与 PK 发言、方案导入导出、为骑士和守墓人增加有回归测试的专用操作。优先补完整玩法处理，再扩充牌库。

## Build 17 实际试用后的调整

此次根据主持人实际使用反馈修正了主流程，未重新打包或推送。

- 选择固定板子后，座位页仅允许与本局另一座位互换身份，保持阵容人数与牌数不变；需要改阵容时显式进入自定义编辑。
- 赛前规则、口播编辑及本局图鉴按实际阵容筛选，关闭警长时不显示警长票权，本局没有的守卫、猎人、跟随和带人设置不混入当前流程。
- 主持页首先展示大字重点与完整口播；赛中反复出现的通用规则、角色介绍和技能实现说明移至赛前确认或备用查阅。
- 夜间第一项行动包含闭眼开场；公布死亡、发言、投票、出局技能和警徽处理直接写明可公开的座位。夜间身份与目标反馈保留在私密区。
- 投票放逐、出局技能或警徽处理后，刚刚公开的结果跨越自动阶段切换继续显示，避免进入下一夜就看不到刚出局的是几号；下一步实际操作开始后收起。
- 增加明确的 `skip-night` 动作处理本夜不行动与已出局角色；既有的不开枪、放弃带人和撕毁警徽操作保留，按钮改为完整宽度，避免被并排压缩。
- 手动天亮名单不再要求主持人每次键入复核理由。未填补充说明时记录“已按赛前桌规核对”，仍保留明确的名单和出局原因确认。

验证：13 个 Jest 测试套件、200 项测试全部通过，另通过类型检查、ESLint、引擎冒烟、回归检查和差异空白检查。包含固定板身份互换、无关角色与规则隐藏、完整口播与隐私、出局后跳过/不发动、名单无键入确认，以及放逐后结果保留的 UI 回归。未连接 Android 真机验证显示效果。

## 三个独立入口与卡牌技能表（2026-11-14）

主界面改为底部三个入口，依次是“主持、技能表、个性化”。主持首页保留新建、继续对局、默认方案摘要和复盘；原本堆在首页的模式选择移到第三页。开局设置、方案编辑、实际主持和复盘详情使用各自页面，不同时叠加主导航和对局导航。

技能表覆盖当前注册的 31 种牌，列表直接展示角色、阵营、核心技能和发动时机。可按名称、技能或限制搜索，按阵营筛选；详情包含完整技能、限制、主持提醒、软件处理范围和参考来源。技能表不接收对局数据，不展示实际玩家的秘密身份。独立技能表与赛前、赛中的备用查阅共用角色详情组件，避免出现两份不同说明。

个性化页集中管理默认开局方式与主持方案。主持人可在方案编辑中调整阵容、桌规、平票、夜间顺序、完整台词、计时和补充约定；保存后由新局自动带入。修改偏好时保留原有存储失败提示和写入保护，当前对局保持自身已确认的设置。

## 0.3.0 试用后的第一轮精简与卡牌修正

用户反馈三页面方向接近目标，但设置偏重、卡牌类型与实际技能触发需要更准确。本轮保留现有页面结构，不继续扩充玩法和配置开关。

- 新建对局默认只展开警长、胜负与当前角色的常用技能限制。首日顺序、票权、平票、连守、完整流程编辑和补充约定放到“更多桌规”；编辑常用方案时仍可直接调整全部选项。收起只改变显示，不清空已有规则；完整开场宣读仍按本局全部设置生成。
- 技能目录将基础身份、特殊身份、觉醒身份、附加状态分开。类型筛选在一个弹层里完成，狼王、白狼王与觉醒狼王保持独立条目；这属于目录分类，不宣称所有特殊技能均已自动实现。
- 技能详情默认突出技能、时机与限制；主持说明、实现范围及来源按需展开，部分或人工处理提示仍保留在首屏。
- 幸运儿是保留原身份的附加状态，不再作为新的独立身份配入座位。商人模板已移除固定幸运儿名额。旧方案保持可读，并提供移除该错误名额、补回原身份的路径；已有对局仍可恢复，不静默改写历史。
- 出局技能按角色和死因判断：普通猎人不因被枪带走或殉情再次开枪；被毒按本桌开关；狼美人被毒、刀伤不再触发殉情，放逐/枪类或人工裁定仍有相应处理。殉情不继续触发目标的死亡技能，但警徽仍要处理。白狼王只在自爆后带人。
- 石像鬼从自爆可选座位中排除，引擎同步拒绝该动作。共同狼队身份、石像鬼刀权继承、特殊阵营胜利等更广泛机制仍需另行实现，不因本轮局部修复就标为全自动。

技能依据重新读取网易官网公开角色数据，来源同 `role-reference.ts` 中的 `official-card-data`。当前 `shot` 死因没有细分猎人、狼王等所有枪类来源，狼美人按枪类统一处理；人工裁定 `ruling` 保留主持人处理例外的入口，不冒充普通死因。上述边界在角色详情中说明。

本轮修改尚未重新打包、推送或发布。用户当前已下载的 0.3.0（build 18）不含本轮修改；组件和引擎测试不代替 Android 真机试用。

验证结果：19 个 Jest 套件、242 项测试全部通过，类型检查、ESLint、引擎冒烟、既有流程回归和差异空白检查通过。新增覆盖按死因触发/禁用技能、殉情警长仍移交警徽、自爆列表与实际校验一致、幸运儿新建拒绝/旧存档兼容、卡牌类型筛选及折叠设置不丢失。

## 可用性与现场实用性补齐（2026-11-14）

新增按真实投票人批量录票、直接改已录票、确认剩余弃票；一组操作可一次撤回，警长票权与原有平票规则继续生效。警上、PK 与临时发言／遗言可选席位计时，PK 发言结束后再录票。现场备忘保存私密信息，不推进流程、不清空本步目标。

特殊板子按实际缺失机制生成赛前处理清单，需要时默认启用天亮复核和主持人判定结束；显式保存的选项仍受尊重。加入第三方胜方记录和正确身份分类。自定义阵容在新局首步直接可用；设置返回逐步回退；主持方案支持独立复制并设为默认。

个性化新增“本机数据：备份与恢复”。导入先校验并预览，再明确决定是否替换当前局；数据与原始恢复快照通过 SQLite multiSet 同一事务提交，损坏当前局需明确确认。新增 Android 备份文件保存／选择入口以及文字复盘分享。为文件操作增加与 SDK 58 匹配的 expo-file-system 和 expo-document-picker，未更改应用版本。

补充修复传输锁与此前已接受的归档任务之间的竞争，内部队列读取可先完成；恢复快照保留旧恢复记录而不递归重复嵌套。最终全量验证：33 个 Jest 套件、518 项测试通过；TypeScript、ESLint、引擎冒烟、既有流程回归和差异空白检查通过。收尾禁用不适用阶段的裁定入口，相关 40 项交互回归通过。Android Metro/Hermes 导出通过，696 个模块，字节码 2,094,814 字节。本轮仍未打包、推送或发布，未进行 Android 真机验收。详细交付与边界见 `docs/可用性与实用性改造-2026-11-14.md`。

## 1.0.0 正式版门槛（2026-11-15）

1.0 的目标从“继续增加页面和按钮”改为“主持流程可闭合、失败可恢复、支持边界不误导”。应用版本升至 `1.0.0`，Android `versionCode` 升至 `9`。

- 新增独立遗言阶段。赛前可分别开启首夜夜死、后续夜死、放逐、技能带走和自爆遗言；多个死者按座位排队，逐人确认发言或明确放弃，再继续出局技能、警徽和胜负。
- 白天发言、警上、PK 和遗言可分别计时；旧方案没有分阶段字段时继续沿用原 `speechSeconds`。
- 50 个角色按“自动处理、部分处理、主持人处理”保持真实分类。所有非全自动角色以及需要现场提醒的自动角色都会进入本局技能清单，主持人填写座位、目标、次数或裁定结果后写入私密复盘。
- 31 套板子增加“已验证 / 主持引导 / 实验中”等级。支持等级依据人工角色、未锁定规则和来源可信度生成；已验证板子排在前面，但全部阵容仍可查看和开局。
- 新增 93 个确定性整局场景，覆盖全部 31 套板子、普通流程、PK、手动天亮复核、遗言、特殊夜间行动、出局技能、警徽和复盘往返；1.0.1 又扩展到 124 个场景。
- 存档校验增加存活/死亡记录、死亡警长、待办阶段、投票资格、结束结果和待办队列一致性检查。旧版天亮前过渡状态先尝试安全修复，再执行严格校验。
- 主持提词新增标准、大字、超大档位；次要文字对比度达到小字号可读要求；响应式布局按 2.0 倍系统字体计算。
- 首页保存状态改为“保存中 / 已保存时间 / 保存失败”三种真实状态；最近复盘点具体对局时直接打开对应详情。
- 新增渲染错误恢复页，错误信息不会把玩家名或身份写入界面；可重新挂载界面或导出私密原始存档。
- Android 正式包通过 Manifest merger 移除网络和悬浮窗权限，关闭系统自动备份；CI 使用 `apkanalyzer` 检查最终 APK 权限和 `allowBackup=false`。
- 可为主持端设置 4–8 位数字 PIN，只保存随机盐和 SHA-256 哈希。PIN 默认关闭；适合同一台手机在主持端和玩家模式之间切换的场景。
- Jest 根目录锁定到当前 `scripts/`，不再误跑 `build-output` 中的历史源码备份。

## 1.0 后现场桌规补强（2026-11-15）

- 存档校验覆盖身份确认进度：拒绝重复座位、确认未完成却进入第一夜、确认已满却仍停在确认页等不可达状态；快速放逐拒绝混用逐人录票与计票动作。
- 新增桌规差异专项测试，覆盖默认/显式关闭空唤醒、身份确认逐人推进与存档、快速放逐直接出局、无人出局、界面入口，以及快速放逐后遗言→猎人→警徽的完整后续链路。
- 每个身份分别验证“存活 / 出局 / 本夜被恐惧”状态，修复存活角色被恐惧时误显示“已出局”的文案和跳过原因。快速模式同时隐藏放逐平票、PK 与 PK 计时，并拒绝保存带轮次、投票人或逐人票的快速放逐状态。
- 最终验证：74 个 Jest 套件、1000 项通过、30 项明确 todo；TypeScript、ESLint、引擎冒烟、既定回归、Expo Doctor 20/20 通过。Android Hermes 导出 874 个模块，字节码约 2.6 MB。所有板子矩阵为 31 × 4 = 124 个场景。
