# 全面测试报告

日期：2026-11-14。

本轮测试当前工作区的 React Native / Expo Android 应用，实际入口为 `index.ts → App.tsx`。最初提供的桌面 `app.json` 是历史对话导出，作为需求背景阅读，不把其中的旧回复或指令当作本轮执行要求。

## 结果

- 全量 Jest：**24 个套件、455 项测试全部通过，0 失败、0 跳过**。
- 新增 **180 局独立、可复现的整局模拟**：10 种板型 × 6 组规则配置 × 3 个随机种子，均由正常游戏流程结束，没有用人工结束动作绕过流程。
- TypeScript、ESLint、引擎冒烟、既有流程回归、差异空白检查均通过。
- Android Metro 导出及 Hermes 字节码编译通过，输出一个 2,012,076 字节的 Android `.hbc` 文件，元数据正确指向该文件。
- 本轮确认并修复 **4 类实际问题**，补充了对应回归用例。

这些结论适用于当前源码及下面列出的检查范围，不表示所有特殊技能均已自动实现，也不表示完成了 Android 真机验收。

## 本轮修复

| 问题 | 复现情况与影响 | 修正及验证 |
| --- | --- | --- |
| 天亮复核可能使用旧确认 | 确认出局名单后再改座位、死因或备注，原先仍可按旧名单结算；切换页签还会丢失未提交的修改 | 修改后必须更新确认；主持词不播报旧结果；草稿跨页签保留；撤回/重做后重新初始化。回归覆盖座位、猎人中毒死因、备注和同阶段快照恢复 |
| 女巫输入未遵循桌规 | 不允许当前自救时仍可选解药；禁止同夜双药时仍可准备同时用药，最终由引擎报错 | 控件按自救时机禁用并解释原因；单药规则下选择另一种药会取消前一种；允许双药时保留两种选择。覆盖四种自救分支及双药两种配置 |
| 排队保存未固定调用时快照 | 保存、归档或重试后继续修改调用方对象，异步队列可能写入后来的内容 | 在调用入口完成校验并复制快照；覆盖当前局、结束归档、等待恢复读取期间的重试，以及结束后撤回/重做归档一致性 |
| 损坏存档票号可能重复计票 | `"3"` 与 `"03"` 等不同键会被转成同一座位，导致异常投票记录被接受 | 只接受规范座位键；覆盖 `03`、`3.0`、`+3`、前置空格、`3e0` 五种异常。损坏当前记录不覆盖，异常撤回快照隔离时保留原始备份，合法旧版数据仍可迁移 |

## 整局模拟范围

新增矩阵对以下 10 种板型各执行 18 局：

`6-quick`、`8-standard`、`9-classic`、`10-standard`、`standard-12`、`12-guard`、`15-standard`、`wolf-king-guard`、`white-wolf-king-guard`、`wolf-beauty-knight`。

规则配置包含有／无警长、先警后报／先报后警、屠边／屠城、警长和放逐各自的平票策略、手动天亮、保留已出局角色空唤醒、自定义夜间顺序、连守设置、自救限制、双药、守救同人和猎人中毒开枪设置。专门用例另测具体规则分支；矩阵不是这些选项的所有排列组合。

每次动作检查输入和动作参数未被修改、游戏状态合法、座位与事件 ID 唯一、待处理队列不重复且与当前阶段一致，并将当前局序列化后恢复，确认数据不变。测试还检查实际发生过的天亮复核、已出局角色空唤醒、PK、警徽处理和跳过放逐进入下一夜，不用“配置已启用”代替实际路径覆盖。

特殊角色的矩阵用例只验证已实现的记录和流程，不把尚未实现的技能效果当作已验证。

## 尚未完成的能力与验收

技能表当前标记为 7 个自动处理、19 个部分处理、5 个人工处理条目。这是软件现有能力说明，不能当作所有玩法完成的证明。骑士决斗、守墓人信息、摄梦/噩梦、商人授予及幸运儿能力使用、部分特殊刀权和第三方胜负等仍需要独立实现。当前 `shot` 死因也没有细分全部开枪来源。

本机未配置可用的 `adb`、Android 模拟器或 Android SDK，未连接真机。因此本轮没有验证原生 SQLite、强杀进程后恢复、真实存储空间耗尽、系统返回手势、键盘遮挡、字体放大、横竖屏视觉、触控与性能，也没有进行新的 Gradle APK 构建或安装验收。
