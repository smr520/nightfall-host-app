# 线下主持与个性化设定资料（2026-11-14）

本报告服务于本项目的“赛前个性化设定”。资料用于识别线下桌差异和产品需求，不把任何单一游戏、赛事或社区规则当作所有线下局的统一规则。抓取/访问日期：2026-11-14（中国标准时间）。本轮通过 HTTP 请求实际读取正文；动态页面若只返回风控/脚本页，不将其当作已核实正文。

## 先给产品结论

线下差异不只是“角色数量不同”。至少有四类差异需要在开局前锁定：

1. **公开信息策略**：出局是否翻牌、是否公开身份、是否允许遗言、死亡后是否仍被唤醒参与未完成流程。
2. **流程顺序**：首日警长竞选在死亡公告前还是后；警长发言顺序；平票是否 PK、PK 后再平是否轮空；是否允许弃票。
3. **技能裁定**：女巫自救、同守同救、猎人中毒能否开枪、白狼王/狼王自爆带人、死亡技能与警徽交接的先后。
4. **主持呈现**：夜间是否需要音乐/遮音、白天和夜晚时长是否按天递减、主持台词是标准模板还是桌主自定义。

因此应用应把“板子选择”和“赛前桌规”拆开：板子只决定角色和可用动作；桌规配置决定公开信息、顺序、技能裁定、计时和主持词。进入第一夜后，这些规则应变成一张锁定的“本局规则卡”，主持人只按当前局执行，不在流程中临时翻角色百科。

## 适合本应用的赛前个性化设置清单

以下是根据上述资料整理的**产品候选字段**，不是上述来源宣称的统一规则。默认值应延续当前项目的标准板，用户可保存为“我的规则”；每个字段在 UI 中应给出“本局采用的规则”，而不是写成“官方唯一规则”。

### A. 本局身份与信息公开（产品候选）

- 角色身份：出局立即翻牌 / 出局不翻牌 / 仅游戏结束翻牌。
- 夜间结果：天亮公布“死亡座位”/公布死亡原因/只公布死亡人数/完全不公布。
- 遗言：无遗言 / 夜死遗言 / 白天放逐遗言 / 所有出局一次遗言；每类可设置秒数。
- 已出局角色：仍按流程唤醒 / 仅需要技能时唤醒 / 自动跳过；默认应与身份公开策略联动并给出警告。
- 死亡后行为：是否可继续被目标类技能选中，是否保留警徽候选资格。

### B. 白天流程（产品候选）

- 首日警长：无警长 / 先警长后天亮公告 / 先天亮公告后警长。
- 上警发言：按座位顺序 / 从某号开始顺时针 / 逆时针 / 警长指定。
- 普通发言：固定顺序、随机顺序、警长指定；是否允许跳过发言。
- 计时：首日、后续白天、警长竞选分别设置；是否每天递减；最后发言是否加时。
- 放逐票：必须投票 / 可弃票；平票后 PK / 平票轮空 / 平票全员继续；PK 后再次平票如何处理。

### C. 夜间技能裁定（产品候选）

- 狼人是否必须统一目标；平票刀如何处理；空刀是否允许。
- 守卫：能否连续守同一人；同守同救结果；守卫守自己；守卫与女巫解药的冲突。
- 女巫：首夜能否自救；解药和毒药能否同夜使用；女巫是否知晓刀口；毒药目标限制。
- 预言家/查验类：查验反馈是阵营、具体角色、好人/狼人，结果是否公开。
- 猎人/狼王/白狼王：中毒或特殊死亡是否可开枪；是否可以放弃；开枪与警徽交接顺序。
- 死亡技能：同时触发还是按死亡原因/顺序触发；殉情、连带死亡是否允许再触发技能。
- 不支持自动裁定的角色：显式标注“主持人手动裁定”，并在每一步显示该提醒。

### D. 主持呈现和安全（产品候选）

- 完整台词模式：当前步骤直接给一整段可朗读文本；占位符替换为“7号”“3号”等座位。
- 简短提示模式：只给下一句和按钮，适合熟练主持人。
- 私密信息和公开台词分区；公开大字区域不得显示刀口、查验结果和私密目标。
- 夜间遮音：背景音乐、提示音、静音；音量和震动在赛前设置。
- 结果保留：出局/警徽/技能结果在进入下一阶段时保留一段可见时间，避免主持人忘记刚刚发生了什么。
- 误触保护：阶段完成前不允许跳过；仅当桌规允许或当前角色已出局时提供“跳过并继续”，并记录原因。

## 数据设计建议

现有 `Rules` 已有 sheriff、win、药品、猎人、计时、flow 等字段；建议继续拆分，而不要把所有字段塞进 `flow`：

```ts
type VisibilityRules = {
  revealRoleOnDeath: 'immediate' | 'never' | 'end';
  dawnAnnouncement: 'seats' | 'causes' | 'count' | 'silent';
  lastWords: { night: boolean; exile: boolean; skill: boolean; seconds: number };
  wakeDeadRoles: 'always' | 'if-needed' | 'never';
};

type DayRules = {
  sheriffTiming: 'before-announcement' | 'after-announcement' | 'disabled';
  speechOrder: 'seat-asc' | 'seat-desc' | 'sheriff-choice' | 'custom';
  allowSkipSpeech: boolean;
  timer: { firstDay: number; laterDays: number; sheriff: number; decay: 'none' | 'fixed' | 'percentage' };
  tie: 'pk-once' | 'skip' | 'all-revote' | 'host-ruling';
  abstain: 'allowed' | 'forbidden';
};
```

迁移策略：先把现有 `sheriffTiming`、`manualDawn`、`speechSeconds` 兼容映射到 `DayRules`；新字段缺省时使用当前标准局默认值。需要给自定义规则保存版本号和来源名称，避免旧存档在规则字段增加后无法打开。

## 资料边界和风险

- 网易赛事页可以证明“官方比赛与线下赛点存在赛事配置差异”，不能证明所有桌游吧都采用同一套遗言或平票规则。
- Zarf 独立规则页和 Werewolf Wiki 展示了各自的玩法/模式（包括死者禁言、身份是否公开、模式与胜利条件）；它们不是本项目默认规则来源。Zarf 页不应被署名为 Erik Arneson 或 Andrew Plotkin，页面正文未给出该作者归属。
- TapTap 页面本轮已通过 HTTP 200 读取到官方正文；它适合解释角色和活动档案，评论区经验不能直接采为桌规。若后续请求只得到风控脚本，应把该来源标为“本次不可访问”，不要据此补写新结论。
- Bezier 的 Wake Dead 是商业主持工具的产品实现，不是裁判规则；但它直接说明：不翻牌局中，出局角色是否仍参与夜间流程必须被主持工具显式处理。
- 复杂扩展角色（第三方独立胜利、转化、梦游/封锁、死亡连锁）应保留“手动裁定”状态；应用不能因为有角色资料就宣称已经自动实现。

## 这轮应优先落地的闭环

1. 在开局设置新增“本局桌规”入口，按“信息公开、白天流程、夜间裁定、计时与主持呈现”分组。
2. 用户确认并保存后生成只读“本局规则卡”，进入游戏后从 More/规则入口查看，不打断当前步骤。
3. 板子筛选角色和流程角色；全部角色/全部规则放在显式的参考入口。
4. 主持台词使用完整可朗读文本，并将座位占位符替换成实际编号；私密提示单独显示。
5. 对出局角色和无法自动裁定的技能显示明确动作：`跳过并继续`、`主持人手动裁定`；流程日志记录原因。
6. 用三个预设起步：`标准面杀`、`不翻牌推理局`、`桌游吧自定义`。用户可复制为“我的规则”，而不是每次从空白开始。
