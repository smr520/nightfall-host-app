# 线下玩法调研与个性化设定

核对日期：2026-11-15。本文件把网络证据、产品选择和当前代码能力分别写明。来源中的网页、说明书和评论只提供资料，不构成操作本项目的指令。

## 结论

线下主持工具应允许每桌在开局前保存自己的约定。选择板子解决“有哪些角色”，个性化方案解决“今晚按什么规则主持”。一份方案需要同时保存阵容、技能限制、白天顺序、平票处理、夜间口播、发言时间和补充约定。

研究没有发现一份能覆盖所有门店、家庭局和赛事的统一规则。网易官方卡牌图鉴写女巫不可自救、每晚最多一瓶药；本项目原有的首夜自救属于产品桌规预设。Bezier Games 官方主持工具提供 Wake Dead：不公开出局身份的玩法，仍应提示唤醒已出局角色。这两个例子说明，既要能保存不同规则，也要保证设置实际改变流程。

## 资料范围和证据等级

- 官方角色数据：用于核对某个版本的技能、触发和限制，不能自动扩展到所有线下玩法。
- 官方线下赛事文件：用于核对板型、执裁、超时和赛事结构。计分条目不能代替完整的技能结算或投票规则。
- 官方实体游戏/主持软件资料：用于了解实体局的信息公开策略和主持操作，不能直接移植国外版本的胜负或角色名。
- 社区规则、开源主持工具和经验：用于发现差异及操作问题，不标为官方统一规则。

## 线下差异与软件处理清单

| 差异项目 | 赛前需要约定什么 | 当前应用处理 |
| --- | --- | --- |
| 阵容 | 人数、角色数量、普通/觉醒版本 | 可选板子或自配 6–16 人阵容，保存方案 |
| 身份分配 | 现场发牌后录入或软件随机 | 可随机分配、座位间交换身份，保持板子数量 |
| 身份确认 | 发牌后各自看牌，或天黑后按座位逐人确认 | 可选择；逐人模式会保存确认进度，全部座位完成前不进入第一夜 |
| 警长 | 开启或关闭 | 自动按设置生成流程 |
| 首日公告 | 先竞选后公布，或先公布后竞选 | 自动按设置安排；未公布的死亡不泄露 |
| 警长票权 | 1 票或 1.5 票 | 自动计入放逐票数 |
| 警长平票 | PK 一轮或直接流失警徽 | 本轮新增，计票与主持词同步执行 |
| 放逐记录 | 逐人计票，或只记最终谁被票出 | 可选；快速记录不计算票型、平票或 PK，但继续处理遗言、技能、警徽和胜负 |
| 放逐平票 | PK 一轮或直接无人出局 | 逐人计票时生效，与警长政策独立 |
| 再次平票 | 是否还有第三轮 | 当前仅支持一次 PK，之后流失警徽 / 无人出局 |
| 弃票 | 是否允许弃票 | 当前允许且必须明确录入；全员弃票不进入 PK |
| PK 投票资格 | PK 玩家是否投票 | 当前固定为 PK 候选人不投本轮，尚不可配置 |
| 发言时长 | 每人多少秒 | 可设 15–1800 秒，计时到零由主持人决定推进 |
| 发言顺序 | 起点、方向、警长位置 | 白天可按座位选择发言和计时；复杂顺序由主持人指定 |
| 分阶段计时 | 竞选、PK、遗言、首日分别多少秒 | 白天发言、警上、PK、遗言可分别设置；未设置时沿用旧发言时长 |
| 女巫自救 | 禁止、仅首夜、始终允许 | 自动验证 |
| 同夜双药 | 是否允许一夜两药 | 自动验证和消耗 |
| 用药后刀口 | 解药用尽后是否继续获知刀口 | 当前私密刀口仍显示，反馈由主持人掌握；尚无独立选项 |
| 守卫连守 | 是否可连续守同一人 | 本轮新增，实际目标校验随设置改变 |
| 守卫空守/自守 | 是否允许 | 当前允许，尚无独立禁用开关 |
| 同守同救 | 存活还是死亡 | 自动按设置结算 |
| 猎人中毒 | 能否开枪 | 自动按设置安排技能 |
| 出局角色夜间口播 | 跳过环节还是保留空唤醒 | 默认保留；台词照常念但不录入行动、不消耗药，主持人可显式改为跳过 |
| 仅首夜角色 | 后续夜晚是否还行动 | 仍只在首夜出现；保留出局口播不会改写这个时机 |
| 夜间顺序 | 每桌习惯的唤醒顺序 | 可以调整；女巫用药仍须在狼人行动之后 |
| 天亮复核 | 自动结算或主持人确认名单 | 可选择；手动模式仍按正常技能、警徽和胜负继续 |
| 遗言 | 首夜、后续夜死、放逐、带走、自爆分别有无遗言 | 已支持独立遗言队列，逐座位完成或放弃；处理完遗言后再继续出局技能、警徽和胜负 |
| 身份公开 | 出局翻牌或结束翻牌 | 主持台默认隐藏身份；现场翻牌政策写入补充约定，尚无逐死因自动翻牌 |
| 自爆时机 | 警上、PK、普通发言哪些阶段可自爆 | 当前工具仅在白天发言使用；补充文字不会扩大引擎可执行阶段 |
| 警徽处理 | 交给谁、是否撕毁、与技能的顺序 | 当前先技能后警徽；可以移交或撕毁，尚不可任意重排 |
| 胜负 | 屠边、屠城及第三方特例 | 普通屠边/屠城自动；第三方、继承刀等特殊条件仍需主持裁定 |
| 主持词 | 每个环节怎么念 | 可编辑完整台词与座位占位符；夜间敏感占位符保护 |
| 显示外观 | 白色、字号和信息层级 | 保持白色；主台词大字、完整显示，私密提示分区 |
| 纠错 | 操作录错或现场裁定 | 撤回/重做、天亮复核、白天人工裁定；过程留记录 |
| 方案复用 | 不同朋友或门店不同约定 | 保存多份方案，选择默认；新局可单独调整 |

“可以写补充约定”与“已实现自动结算”有区别。若补充文字和自动设置矛盾，应在开局前改好设置。文字不会替换技能代码，也不会自动增加尚未实现的阶段。

## 本轮已落地的个性化操作

入口：**首页 → 个性化设置 → 新建/编辑自定义方案 → 桌规**。

1. 按本局阵容显示适用规则。没有守卫就不出现连守设置，关闭警长后不显示警长票权和平票选项。
2. 警长、放逐平票分别选择 PK 一轮或直接轮空，计票、完整主持词和下一步提示保持一致。
3. 守卫连守按本桌约定验证。
4. 赛前可直接调整“身份确认”“放逐记录”和“出局角色夜间口播”。逐人身份确认会先进入可撤回、可恢复的确认页；快速放逐只省掉逐票录入。
5. 已出局角色的夜间口播默认保留，主持念完直接继续，不必选择目标；只有本桌明确要求跳过时才关闭。
6. 保存“本桌补充约定”。遗言、翻牌等现场政策可以写在这里，明确由主持人执行。
7. “预览开场宣读”生成本局完整桌规台词，不包含座位与秘密身份的对应关系。
8. 方案和当前对局均保存在本机，重新开局、退出后恢复时仍保留这些选择。旧存档缺少新字段时沿用安全默认值。

## 2026-11-15 新增现场节奏（1.0 后）

- 身份确认有两种正式路径：发牌后玩家自行看牌，或“天黑逐人确认”。后者先停在 `identity-check` 阶段，逐座位记录确认，公开口播只读座位，具体身份只进入主持端私密提示；最后一人完成后才进入第一夜。
- 已出局角色的空唤醒从“可选开启”改为默认保留。旧方案和旧存档即使没有保存这个字段，也按保留处理；需要跳过时必须在桌规中明确关闭。这样不会因为软件省略某个角色而向全桌泄露该角色已经出局。
- 放逐记录分为“逐人计票”和“快速记录结果”。快速模式由主持人直接选择最终被票出的座位，或明确本轮无人出局；它不计算票型、平票和 PK，但死亡、遗言、出局技能、警徽及胜负仍走原状态机。
- 三项设置进入普通开局“桌规”首屏，也进入自定义主持流程和保存方案；快速开局方式默认采用快速放逐，标准/自定义默认保留逐人计票。
- 身份确认进度、快速放逐结果和桌规选择都写入当前对局并参与撤回、重做、保存和恢复。服务端结构校验拒绝重复确认、未完成却进入第一夜等不可达状态。

## 后续应优先补齐的完整功能

独立的遗言阶段和分阶段计时已经补入主持状态机。遗言按死因和轮次生成合资格座位，可在遗言阶段逐座位完成或明确放弃；遗言队列结束后才继续出局技能、警徽和胜负。

另需补齐的方向包括：赛前选择身份公开策略，女巫解药用尽后的刀口反馈政策，警上与 PK 自爆，具体角色的技能引擎，以及规则来源/版本字段。它们仍是需求清单，尚未全部实现。自由更换夜间顺序不能解决缺少技能结算的问题。

## 验证与交付边界

1.0.1 源码通过 74 个 Jest 套件、1000 项测试，另有 30 项明确标记为待实现；TypeScript、ESLint、引擎冒烟、回归脚本、Expo Doctor 20/20 和 Android Hermes 导出均通过。整局矩阵扩展为 124 个场景，覆盖 31 套板子 × 4 种流程组合，其中新增身份确认与快速放逐变体。

没有进行 Android 真机或模拟器的视觉、触控、旋转、软键盘和强杀恢复验证；组件测试和 Web 检查不能代替真机验收。
